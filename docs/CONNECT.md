# Подключение отдельного Telegram-бота

Бот не регистрировался; реальные сообщения не отправлялись. Инструкция предназначена для последующего подключения владельцем.

## Что нужно

- Токен **отдельного** бота от официального [BotFather](https://t.me/BotFather), созданного владельцем. Не использовать токен другого проекта.
- Подтверждённые владельцем Telegram user ID сотрудников; username и телефон не подходят.
- Новая база `DB_PATH` с правами только для процесса и резервным копированием.
- Постоянно работающий Python-процесс с HTTPS-доступом к `api.telegram.org`. Для теста подойдёт собственный компьютер. Для постоянной работы нужно отдельное эксплуатационное решение; GitHub Pages Python не запускает.

## Переменные окружения

Приложение читает окружение процесса; `.env` автоматически не загружается. `.env.example` — только шаблон. Токен нельзя помещать в исходники, репозиторий, скриншоты, аргументы команд и отчёты.

Из папки проекта в bash/zsh токен можно ввести скрыто, без его попадания в историю shell:

```sh
printf 'Токен отдельного бота: '
read -r -s BOT_TOKEN
printf '\n'
export BOT_TOKEN
export STAFF_IDS='ВСТАВЬТЕ_ПОДТВЕРЖДЁННЫЕ_ID_ЧЕРЕЗ_ЗАПЯТУЮ'
export DB_PATH='data/telegram.sqlite3'
export POLL_TIMEOUT='25'
umask 077
python3 -m repairbot check-config
```

Замените `STAFF_IDS` положительными числовыми ID реальных сотрудников через запятую. На Windows задайте те же переменные через настройки окружения или секреты процесса; команда `read` выше относится к bash/zsh.

Проверка формата не обращается в сеть и не доказывает подлинность токена. Для явного запуска **настоящих ответов**:

```sh
python3 -m repairbot telegram --allow-network
```

Сначала выполняются `getMe`, `getWebhookInfo`. При существующем webhook запуск останавливается без перенастройки бота. Нужен отдельный бот или самостоятельное решение владельца о webhook. Учебная база с таблицей `demo_messages` блокируется: она не подходит для реальных ответов и file_id.

Не запускайте два polling-процесса для одного токена или базы. Бот отвечает входящим пользователям. Автоматической рассылки уведомлений при смене статуса нет: клиент запрашивает карточку/историю. Остановка: Ctrl+C, затем `unset BOT_TOKEN`. При утечке владелец перевыпускает токен в BotFather.

## Приёмка после подключения

Проверять только в разрешённом владельцем тестовом диалоге: `/start`, заявка с реальным тестовым фото, отказ от телефона, собственный контакт после согласия, просмотр своей заявки, отказ второму тестовому пользователю, статус сотрудника, перезапуск. Эти сетевые проверки **не выполнены**.

## Данные и ограничения

Хранятся Telegram ID, устройство, описание, file_id фото (файл не скачивается), добровольный телефон и время его передачи, статусы и история. `/cancel` удаляет черновик. `/withdrawcontact НОМЕР` удаляет телефон из заявки и локальной очереди ответов; уже доставленные сообщения, копии в учебном диалоге, резервные копии и данные Telegram не отзываются. До подтверждения заявки телефон временно хранится в черновике после явного согласия.

Для рабочего запуска владелец определяет сроки хранения/удаления черновиков, заявок, журналов и резервных копий, готовит свою политику обработки данных, защищает доступ к файлам. Готовой юридической политики и шифрования SQLite приложением нет.

Изменение заявки, входящий update и очередь ответов фиксируются одной транзакцией. Повтор одного update_id в течение 7 дней не создаёт дубль. Устаревший offset сбрасывается после 6 дней: Telegram может изменить последовательность ID после недели без событий. Сеть/429/5xx оставляют ответ в очереди; retry_after соблюдается полностью. 401/409 останавливают процесс. Постоянные ошибки доставки сохраняются в dead-letter строках outbox для разбора.

Если Telegram принял сообщение, а процесс упал до отметки в SQLite, исходящий ответ может повториться. Интерфейса повторной отправки dead-letter, мониторинга, автоматической очистки и масштабирования в поставке нет. Один runner на базу.
