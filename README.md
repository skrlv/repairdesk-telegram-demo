# Приёмная · Telegram-бот мастерской

Демонстрационный проект: неисправность, фото, добровольный контакт, статусы, история. Бот не зарегистрирован; настоящее подключение и отправка сообщений не выполнялись. Все примеры учебные.

## Публичная витрина и исходники

[Посмотреть сценарий](https://skrlv.github.io/repairdesk-telegram-demo/) · [Репозиторий](https://github.com/skrlv/repairdesk-telegram-demo) · [Скачать ZIP](https://github.com/skrlv/repairdesk-telegram-demo/archive/refs/heads/main.zip) · [Инструкция на витрине](https://skrlv.github.io/repairdesk-telegram-demo/instructions.html).

Витрина переключает готовые учебные сообщения. Она не создаёт заявки, не хранит контакты и не обращается к Telegram. Реальное ядро Python/SQLite запускается отдельно на вашем компьютере.

Скачайте и распакуйте ZIP. Откройте терминал в папке `repairdesk-telegram-demo-main`, рядом с README.md и папкой repairbot/; выполните команду ниже. Также можно клонировать репозиторий.

## Запуск за минуту

Нужен Python 3.9 или новее, внешних Python-зависимостей нет. Из папки проекта:

```sh
python3 -m repairbot demo
```

Откройте <http://127.0.0.1:8783/>. На Windows: `py -3 -m repairbot demo`. На macOS можно открыть `start-demo.command`. Остановка: Ctrl+C. Если порт занят: `python3 -m repairbot demo --port 8793`.

## Сценарий для заказчика

1. Как «Клиент А» нажмите «Новая заявка». Введите «Ноутбук (демо)» и описание от 10 символов.
2. Камера передаёт **учебную иллюстрацию**, а не файл с устройства. Либо отправьте `/skip`.
3. Выберите согласие на телефон или продолжение без него. После согласия кнопка передаёт синтетический контакт `+00000000000`. В Telegram принимается только собственная контактная карточка, а не номер текстом.
4. Проверьте карточку, нажмите «Создать заявку». До подтверждения хранится черновик.
5. Переключитесь на «Клиент Б»: `/ticket 1`, `/history 1` — чужая заявка и фото недоступны.
6. Как «Сотрудник» откройте все заявки, карточку и пройдите «Диагностика → В ремонте → Готова к выдаче → Выдана». Откройте историю.
7. Вернитесь к клиенту А: `/mine`, `/ticket 1`, `/history 1`. Отзыв телефона: `/withdrawcontact 1`.

Учебная база `data/demo.sqlite3` хранит заявки, черновики и диалоги между запусками. Чистый показ: `python3 -m repairbot demo --db data/another-demo.sqlite3`. Стенд слушает только `127.0.0.1`; не публикуйте его через туннели. Переключатель ролей — инструмент стенда, а не аутентификация.

## Комплект

- `repairbot/core.py` — общее ядро с правами и состояниями для стенда и Bot API.
- `repairbot/demo.py`, `web/` — локальный интерфейс к настоящему ядру.
- `repairbot/telegram.py` — отдельно включаемый HTTPS long polling и очередь ответов.
- `repairbot/config.py`, `.env.example` — переменные окружения; секрет не печатается.
- `tests/` — проверки состояний, доступа, согласия, ошибок, повторов и перезапуска без сети Telegram.
- `showcase/` — отдельная **статическая иллюстрация** для портфолио, без базы и подключения к Python.
- `.github/workflows/pages.yml` — тесты и публикация только `showcase/` официальными GitHub Actions.
- [Подключение](docs/CONNECT.md), [устройство проекта](docs/ARCHITECTURE.md).

`showcase/index.html` можно открыть отдельно или через публичную витрину выше. Полноценный диалог требует запуска Python. Официальный workflow сначала выполняет тесты и публикует только showcase/. Папки repairbot/, web/, docs/ и tests/ доступны в исходном репозитории, но не в Pages.

```sh
python3 -m unittest discover -s tests -v
```

Историческая локальная приёмка №03 сохранена отдельно от репозитория. Новая публичная проверка №50 фиксирует точную опубликованную версию, сценарии и снимки; доставка Telegram в её объём не входит.

Реальный бот потребует отдельного токена, подтверждённых ID сотрудников и постоянного процесса с интернетом. GitHub Pages не выполняет Python. Хостинг и платные услуги не приобретались. Доставка в Telegram и эксплуатационная готовность не заявляются.
